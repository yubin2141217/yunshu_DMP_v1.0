# 产品设计原则

- 清晰高效

    - 信息架构直观，操作路径简短，一个页面只解决一个核心任务。

    - 用最少的步骤帮助用户完成任务，避免无关信息和功能堆砌。

- 包容友好

    - 考虑不同角色、不同熟练度用户的使用场景。

    - 提供及时、清晰的反馈和引导，充分考虑各类操作状态。

- 克制收敛

    - 不做多余的功能，不加无效的修饰。

    - 每一次新增都应经过“是否必要”的审慎考量，优先优化现有问题。

- 一致可靠

    - 保持产品内交互与视觉语言的高度统一。

    - 保障系统稳定、数据准确，让用户产生信任感。

## 页面交互容器

**核心原则**：根据信息量、操作复杂度和上下文关联度，选择最合适的交互容器。以下仅为示例，未涵盖场景根据具体情况选择适合的场景。

### **弹框/模态框**

- 适用场景：

    - 内容极少：只有简单确认、提示或个数较少的表单项。

    - 轻量级操作：无需复杂表单填写或信息浏览。

    - 强上下文：操作依赖于父页面的内容。

- 具体规则：**`（建议执行）`**

    - 大小：通常为页面宽度的30%\-50%。

    - 位置：上下左右居中。

    - 交互：默认情况下点击空白处可隐藏弹框，特殊情况可选择不添加此交互。

    - 内容：尽量一页显示全，不要滚动条，如果默认情况下无滚动条，但是操作后内容增多可能会有滚动条，也不建议使用。

- 示例：

    - 确认删除（“您确定要删除该客户吗？删除后不可恢复，请谨慎操作！”）。

### **抽屉页（右侧滑出）**

该方式慎用。

- 适用场景：

    - 内容量中等：包含一个完整表单或一个对象的详情信息。

    - 操作较复杂：需要多个表单项，但尚未构成一个独立工作流。

    - 与父页面关联紧密：是父页面内容的延伸或新建。

- 具体规则：

    - 宽度：通常为页面宽度的30%\-80%。

    - 行为：支持从右侧边缘滑入，须有关闭按钮（X），支持ESC关闭，点击空白处关闭。

- 示例：

    - 详情：查看下载中心列表，一个页面可以显示完全。

### 文案自检清单

在完成任何文案撰写或评审时，可对照此清单进行检查：

## 统计分析

目标：统计分析页面不仅是数据的展示，更是业务的洞察与决策支持工具。其核心目标是：让用户在最短时间内，理解业务现状、定位核心问题、并获取明确的行动指引。

总体说明：

- 尽量主动呈现数据，不需要让用户有过多的操作。**`（建议执行）`**

- 需要下钻的场景：如果该统计数据在系统中有列表或者统计报表页，则需点击进行下钻。**`（建议执行）`**

### 设计原则

- 目标驱动原则：

    - 每个分析页面或者每个分析图表必须围绕一个明确的、可执行的业务问题构建。

    - 标题应采用“核心指标\+分析维度”的句式（如各环节数据量和效率分析）。

- 信息分层原则：遵循“决策层\-》管理层\-》执行层”的三层信息架构，具体说清楚每个层级关注的点。

    - 决策层：关注总体情况，有没有什么问题？

    - 管理层：问题原因在哪？下一步要如何解决？

    - 执行层：要进行什么操作，才能解决问题？

    具体以数据研判标注系统为例，说明这三层的内容和关系。

    - 决策层：单位时间内`总研判数量：XXX条`，`已完成：XXX条`，`待研判：XXX条`。`日均处理量：XXX条/天`，`人均效率：XXX条/人天`，`平均标注耗时：XX秒/条`。除总览数据外，展示各组数据情况，可以看具体哪组有数据积压。

    - 管理层：组内成员对比图，每个人的数量、效率，具体是某一类型的数据标注影响时效了，还是有其他问题出现。

    - 执行层：待标注的任务列表，如`待处理：XX条`，`今日已完成：XX条`。

- 交互克制原则：主动呈现数据，不需要让用户有过多的操作。

    - 默认展示重要、通用的数据视图。

    - 可以提供一些分析视角，比如近七天、近半年趋势分析等。

    - 对于一些复杂筛选，可以提供“高级分析”、“一键分析”入口，文字说明分析的目的。

- 一致性比较原则：

    - 时间对比：可以适当增加一些同期对比，比如前一日，或者上周同期等。

    - 目标对比：一些关键指标要显示目标值和完成情况，比如网评，今日目标XX条，完成XX条。

    - 基准对比：必要时加一些行业基准或者公司平均值作为参考线。

- 异常导向原则：

    - 对于一些异常点，可以用醒目的颜色标注。

### 基本要求

- 图表类型可以匹配要解答的问题。

    - 展示核心聚合数据：KPI卡片、仪表盘。

    - 表达趋势：折线图、面积图；

    - 部分与整体比较：饼图（≤5类）、环形图、堆叠柱状图；

    - 项目间比较：柱状图/条形图\(离散数据的分布\)；

    - 数据分布：散点图、直方图\(连续数据的分布\)、箱形图；

- 真实、完整地反映数据，站在用户角度审视图表数据。

### 交互

1、鼠标悬停提示（Tooltip）：

- 鼠标形态：当鼠标悬停在任何可交互的数据图形（如柱子、折线点、饼图扇区、图例）上时，鼠标指针应立即变为手型，向用户明确暗示“此处可交互”。

# 安全规范

## 会话安全

- 会话超时：MT系统，可以不登出。客户端系统，如15分钟内不操作可以采用锁屏方式。

## 访问控制与权限安全

- 所有权限校验须在服务端执行，防止水平（验证用户是否能操作他人数据）与垂直越权（执行高权限操作）。

## 数据安全与隐私保护

- 敏感信息（身份证、手机号）须加密存储。

- 数据传输全站HTTPS，日志中禁止记录敏感信息。

## 输入输出安全

- 防SQL注入。

- 文件上传：对上传的文件进行重命名、病毒扫描。

## 业务逻辑安全

- 防重复提交：通过Token机制或前端防抖实现重要操作的幂等性。
