# 云数中台 接入方案管理字段库与接入方式调整 设计方案

## 一、项目概述

本方案对 MT 运营端「接入方案管理」新增/编辑页（`/standard/edit[/:id]`）的三步配置流程做局部调整，涉及第二步「字段库配置」与第三步「接入方式」两个步骤。调整目标：

1. **字段库配置**：新增 Json 批量导入入口，按供数方实际报文一键解析并勾选字段，降低人工逐字段勾选成本，并允许在导入过程中把缺失字段直接补入字段库。
2. **接口地址**：将原单输入框拆为「网关（只读）+ 路由（可编辑）」两部分，路由可自动生成，地址全局唯一并强校验。
3. **接入方式（HTTP 分支）**：精简字段，移除重试/响应码/请求头/鉴权 Header 等低频配置项，AppKey 精简为单字段（删除 AppSecret），新增「接口响应码」列表模块以替代原成功响应码单字段。

调整范围限于 `mt-web` 工程，不涉及 SRS 已定义的菜单结构、字段库管理页、IP 白名单、供数方管理等模块。

## 二、功能范围

| 编号 | 模块 | 调整内容 |
| --- | --- | --- |
| A | 字段库配置步骤 | Json 批量导入按钮 + 弹窗 + 解析 + 缺失字段确认补录 + 自动勾选 |
| B | 接入方式 · 接口地址 | 网关 + 路由拆分，路由自动生成，地址全局唯一性校验 |
| C | 接入方式 · HTTP 字段精简 | 删重试次数/重试间隔/成功响应码；删 AppSecret；删鉴权 Header 名/请求头；删「数据与校验配置」模块 |
| D | 接入方式 · 接口响应码 | 新增列表式「接口响应码」模块（响应码 + 说明，可增删改） |

非目标：MQ / 文件接入分支字段不变；方案列表、详情、文档预览结构不变（详情/文档同步展示响应码区块，但不改其它字段）；字段库管理页（`/metadata`）本身不变。

## 三、核心模块设计

### 3.1 字段库配置 · Json 批量导入（A）

**入口与按钮位置**

在 `FieldPicker.vue` 工具栏的「清空筛选条件」按钮**前**新增 `Json批量导入` 按钮（`a-button type="outline" size="mini"`，与现有按钮同规格）。点击后打开 `a-modal` 弹窗（宽 640），不关闭底层 FieldPicker。

**弹窗结构**

- 标题：`Json批量导入`
- 正文：`a-textarea`（`minRows: 10, maxRows: 18`），placeholder 展示示例：

  ```
  { "name": "张三", "phone": "13800138000", "role": "商务对接人" },
  { "name": "李四", "phone": "13900139000", "role": "技术负责人" }
  ```

- 底部按钮：`取消`（默认） / `解析导入`（primary）

**解析规则（容错）**

1. 先尝试整体 `JSON.parse`：接受数组或单对象。
2. 整体解析失败则降级用正则提取所有顶层 `{...}` 块逐个 `JSON.parse`。
3. 任一块解析失败 → `Message.error('Json 格式不合法，请检查后重试')`，阻断。
4. 提取到的对象数为 0（空内容 / 纯空白 / 非对象） → `Message.warning('请输入有效的 Json 内容')`，阻断。
5. 解析后取所有对象 key 的并集（去重）。

**字段比对与确认**

- 比对对象：当前字段库全部字段的 `name`（已加载到 FieldPicker 的 `props.fields`）。
- 全部存在 → 直接进入导入结果处理。
- 存在缺失 key → 弹二级确认弹窗，文案：`所填写的字段[name、phone、role]不在字段库中，请确认是否新增该字段到字段库中？`，按钮 `取消` / `确认添加`。
- 点「确认添加」→ 调 `saveMetadataBatch` 将缺失字段写入**全局字段库**（mock 持久化）。新增字段默认属性：
  - `dataType`：按 Json 值推断（数字 → `Int`，其余 → `String`）
  - `bizCategory`：`其它`
  - `description`：空
  - `required`：`false`
  - `status`：`enabled`

**导入结果**

- 确认弹窗关闭、Json 导入弹窗关闭。
- FieldPicker 数据源刷新（通过 `emit` 通知父组件重新 `loadOptions`，或通过新事件 `fields-updated` 触发）。
- **解析出的全部字段（含原有 + 新增）自动勾选**进本方案 `editor.fieldIds`，并补全默认 `fieldMaps`（`supplierFieldName` 默认同平台字段名，`supplierDataType` 默认同平台类型）。
- 已勾选字段与解析字段取并集，不丢失原勾选。

**边界**

- 单次导入字段数上限 50（防误粘贴超大文件），超限 `Message.error('单次导入字段数不超过 50')` 阻断。
- 同名 key 在 Json 中出现不同类型时，取首个非空值的类型推断。

### 3.2 接口地址 · 网关 + 路由（B）

**UI 结构**（HTTP 分支「基础信息」模块内，替换原 `apiAccess.endpointUrl` 单输入框）

```
接口地址（全局唯一）                         [唯一性提示 ⓘ]
┌──────────────────────────────────┬──────────────────────────┐
│ 网关 https://ingress.yunshu.example.com │ 路由 /api/v1/push/a1b2c3d4 │
│ （只读，系统配置）                │ （可编辑）                 │
└──────────────────────────────────┴──────────────────────────┘
```

- **网关**：只读输入框，取系统级配置，mock 默认 `https://ingress.yunshu.example.com`（与现有 `defaultApiAccess` 口径一致）。
- **路由**：可编辑；进入第三步时若为空则**自动生成** `/api/v1/push/` + 8 位随机字母数字；格式校验：以 `/` 开头，仅允许字母/数字/`-`/`_`/`/`。
- **完整地址** = `网关 + 路由`，复用现有 `syncEndpointParts`/`buildApiEndpoint` 存入 `endpointUrl`，数据结构不变。

**唯一性校验**

- mock 新增 `checkEndpointUrlExists(url, exceptId?)`：与所有接入方案（含停用）的完整 `endpointUrl` 比对，编辑时排除自身。
- 路由失焦即时校验（表单错误提示）；提交时强校验，重复则 `Message.error('接口地址已存在，请修改路由部分')` 并阻断。
- 字段下方常驻提示（`FormFieldLabel` desc 通道）：`接口地址全局唯一，由系统网关与自定义路由组成，提交时校验唯一性`。

### 3.3 接入方式 · HTTP 字段精简（C）

**删除项**（仅 UI 删除，`ApiAccessConfig` 类型保留字段以兼容历史数据，`normalizeApiAccess` 继续兜底）

| 删除对象 | 位置 |
| --- | --- |
| 重试次数、重试间隔（ms）、成功响应码 | 「流量 & 限流配置」模块（模块保留，仅剩最大 QPS 上限） |
| 鉴权方式选 AppKey 时的 AppSecret | SchemeAppCredentials 精简为仅 AppKey |
| 鉴权 Header 名、请求头 | 「基础信息」模块 |
| 「数据与校验配置」整个模块 | 数据编码 + 开启字段校验一并移除（字段校验行为随现有默认值，不再可配） |

**调整项**

- `apiAuthTypeOptions`：`无鉴权` / `AppKey`（原 `AppKey+AppSecret`）。
- **AppKey**：`SCHEME_APP_KEY_LEN` 调整为 **32**；选择 AppKey 时默认自动生成 32 位字母数字串（沿用 `genSchemeAppKey` 改长度）；可手动编辑，最大 32 位。
- 移除 AppSecret 相关校验规则（`apiAccess.appSecret`）。

**不改动**

- MQ / 文件接入分支的所有字段。
- 「流量 & 限流配置」中的 QPS。
- 编辑已有方案时同样按新交互展示。

### 3.4 接入方式 · 接口响应码模块（D）

**位置**：请求示例上方，样式同现有 `section-block`。

**结构**：

- `apiAccess` 新增 `responseCodes: { code: string; desc: string }[]`。
- 列表两列：响应码（输入，如 200/4xx） | 说明（输入，如「成功」「鉴权失败」），行尾删除按钮，底部「添加一行」按钮。
- 不预置默认行；响应码列做轻校验（数字或含 x 的状态码样式）；空行提交时自动过滤。

**联动**

- 请求示例、方案文档预览（`buildApiDocMarkdown`）同步追加「接口响应码」表格区块。

## 四、数据结构与流向

### 4.1 涉及数据结构变更

```ts
// mt-web/src/mock/mt.ts

// ApiAccessConfig 新增字段
export interface ApiAccessConfig {
  // ... 现有字段不变
  /** 接口响应码列表 */
  responseCodes: { code: string; desc: string }[]
}

// 鉴权选项精简
export const apiAuthTypeOptions = [
  { label: '无鉴权', value: 'none' },
  { label: 'AppKey', value: 'appkey' },  // 原 'AppKey+AppSecret'
]

// AppKey 长度调整
export const SCHEME_APP_KEY_LEN = 32

// 系统级网关配置
export const SYSTEM_GATEWAY = 'https://ingress.yunshu.example.com'
```

### 4.2 新增 API

```ts
// mt-web/src/api/mt.ts
export async function checkEndpointUrlExists(url: string, exceptId?: string): Promise<boolean>
```

### 4.3 数据流向

```
Json 输入 → 解析 → key 并集
  → 比对字段库 → 缺失 saveMetadataBatch → 写入字段库
  → 自动勾选 editor.fieldIds + 补全 editor.fieldMaps
  → FieldPicker fields 数据源刷新

接口地址：网关(只读) + 路由(可编辑) → syncEndpointParts → endpointUrl
  → 路由失焦 checkEndpointUrlExists 即时校验
  → 提交时强校验唯一性

接口响应码：列表编辑 → apiAccess.responseCodes
  → buildApiDocMarkdown 文档预览同步
  → buildAccessExample 请求示例同步
```

## 五、边界情况处理

### 5.1 Json 导入边界

| 场景 | 处理 |
| --- | --- |
| 空内容 / 纯空白 | `Message.warning('请输入有效的 Json 内容')` 阻断 |
| Json 格式不合法 | `Message.error('Json 格式不合法，请检查后重试')` 阻断 |
| 字段数 > 50 | `Message.error('单次导入字段数不超过 50')` 阻断 |
| 全部字段已存在 | 直接勾选，不弹确认 |
| 部分字段缺失 | 弹二级确认，取消则只勾选已存在字段，确认则补录后全勾选 |
| Json 中同 key 不同类型 | 取首个非空值推断类型 |

### 5.2 接口地址边界

| 场景 | 处理 |
| --- | --- |
| 路由为空进入第三步 | 自动生成 `/api/v1/push/` + 8 位随机字母数字 |
| 路由格式不合法 | 表单错误提示「以 / 开头，仅允许字母、数字、-、_、/」 |
| 路由失焦 | `checkEndpointUrlExists` 即时校验，重复则表单错误提示 |
| 提交时地址重复 | `Message.error('接口地址已存在，请修改路由部分')` 阻断 |
| 编辑已有方案 | 排除自身 ID 后比对 |

### 5.3 接口响应码边界

| 场景 | 处理 |
| --- | --- |
| 空行（code 和 desc 都为空） | 提交时自动过滤 |
| 仅 code 有值 | 保留，desc 留空 |
| 仅 desc 有值 | 表单错误提示「请填写响应码」 |
| 响应码格式不合法 | 表单错误提示（轻校验，不阻断保存） |
