# 云数中台 · 数据推送管理设计方案（v1.1）

## 一、项目概述

### 1.1 背景

一期「数据推送管理」原方案将「推送方案」定位为通道/策略模板，由「机构推送任务」挂接机构并启停。经评审调整后：**推送方案即运行单元**，在方案内选定数据范围与推送方式，并可直接查看推送数据量统计；取消独立的机构推送任务。

### 1.2 目标

- 运营可在单条推送方案中完成：基础信息 → 选择推送数据 → 推送方式配置 → 启停与统计查看。
- 数据范围仅来自云数中台**已入库**数据，按机构（单选）× 接入方案（多选）× 供数方（多选）交集筛选。
- 推送方式配置对齐「接入方案管理 · 接入方式」的字段与分区习惯，并补充推送策略（增量/全量、频次、批量等）。

### 1.3 核心价值

- 减少「方案 + 任务」双层维护成本。
- 数据范围与通道策略同屏可配，列表即可看到推送量统计。
- 与接入侧配置心智一致，降低学习成本。

### 1.4 相对 v1.0 的主要变更

| 项 | v1.0 | v1.1 |
|----|------|------|
| 运行单元 | 机构推送任务 | 推送方案本身 |
| 导航 | 推送方案 + 机构推送任务 | 仅推送方案 |
| 编辑步骤 | 基础信息 / 推送通道 / 推送策略 | 基础信息 / 选择推送数据 / 推送方式 |
| 数据范围 | 任务侧「该机构全部已入库」 | 方案内：机构单选 + 接入方案/供数方多选交集 |
| 统计 | 任务列表 KPI | 方案列表/详情展示推送量统计 |

## 二、功能范围

### 2.1 本期包含

1. **推送方案列表**：查询/重置、启停、编辑、详情、复制新增；展示通道类型、推送模式、频次摘要、数据范围摘要、推送量统计。
2. **推送方案新建/编辑（三步向导）**
   - 步骤 1「基础信息」：名称、状态、备注。
   - 步骤 2「选择推送数据」：机构（单选必填）、接入方案（多选）、供数方（多选）；未选维度视为该机构下全部；展示筛选命中估算。
   - 步骤 3「推送方式」：通道配置（HTTP / MQ，文件禁用）+ 推送策略（增量/全量、Cron 或间隔、批量上限；重试与通道流量配置合并一处）。
3. **推送方案详情**：数据范围、通道与策略摘要、统计指标只读展示。
4. **导航调整**：数据推送管理下仅保留「推送方案」。

### 2.2 本期不包含

- 独立「机构推送任务」模块（下线）。
- 文件通道实际投递。
- 真实调度引擎、告警、跨机构单方案多选机构。
- 正式环境级审计与权限细拆（沿用运营角色演示）。

### 2.3 与其它模块关系

| 模块 | 关系 |
|------|------|
| 机构供数配置 | 提供可选机构 |
| 接入方案管理 | 提供可选接入方案；通道表单布局参照其「接入方式」 |
| 供数方管理 | 提供可选供数方 |
| 综合看板 | 总体分析仍归看板；方案仅展示本方案运行统计 |

## 三、核心模块设计

### 3.1 推送方案列表

- 筛选：方案名称、通道类型、推送模式、状态；提供查询 / 重置。
- 表格列建议：方案名称、机构、数据范围摘要、通道类型、推送模式、频次摘要、状态、累计成功、累计失败、最近推送、操作。
- 操作：详情、编辑、启停、复制新增、删除（有运行中约束时可提示仅停用后删除，原型可简化）。
- 列表顶部可选小型 KPI：方案总数、启用中、近 24h 失败总量（由各方案统计聚合）。

### 3.2 编辑向导 · 基础信息

- 方案名称：全局唯一；汉字/字母/数字/下划线，≤100。
- 状态：启用后方可调度；停用后不再推送。
- 备注：可选。

### 3.3 编辑向导 · 选择推送数据

- **机构**：单选，必填；选项来自机构供数配置。
- **接入方案**：多选；选项可按所选机构过滤（无关联数据时展示全部启用方案供演示）。
- **供数方**：多选；同上。
- **范围语义**：已入库数据 ∩ 机构 ∩（接入方案集合或全部）∩（供数方集合或全部）。
- **命中估算**：根据筛选展示「约覆盖 N 条已入库数据」（mock）。

### 3.4 编辑向导 · 推送方式

#### 3.4.1 通道配置（对齐接入方式分区）

- 推送类型：HTTP / 消息队列；文件传输本期禁用。
- **HTTP（外呼）**：对端接口地址、协议、方法、鉴权（无/Token/AppKey）、请求头与 Content-Type、最大 QPS、重试次数、重试间隔、成功响应码、数据编码。
- **MQ（投递）**：队列种类（Kafka/BMQ/RocketMQ）、集群或 NameServer、Topic、必要生产参数；重试次数/间隔。
- 文案相对接入侧改为「中台推送到对端」语义；去掉接入侧「字段校验」等不适用项。

#### 3.4.2 推送策略（精简）

| 配置项 | 说明 |
|--------|------|
| 推送模式 | 增量 / 全量 |
| 频次类型 | Cron 或 固定间隔（分钟） |
| Cron / 间隔值 | 与类型对应 |
| 批量条数上限 | 单次推送最大条数 |
| 重试 | 与通道「流量&限流」合并展示，不维护两套 |

### 3.5 详情与统计

方案详情与列表展示（原型 mock）：

| 指标 | 说明 |
|------|------|
| 累计成功量 | 历史推送成功条数 |
| 累计失败量 | 历史推送失败条数 |
| 最近一次推送量 | 最近一次运行推送条数 |
| 最近推送时间 | 最近一次运行时间 |
| 待推积压量 | 当前筛选范围内尚未推出的估算量 |

### 3.6 导航与下线

- 侧栏「数据推送管理」仅「推送方案」。
- 路由 `/push/tasks` 及任务相关 API/Mock 下线或重定向至方案列表。

## 四、数据结构与流向

### 4.1 推送方案（PushScheme）核心字段

| 字段 | 说明 |
|------|------|
| id / name / status / remark | 标识与基础信息 |
| orgId / orgName | 单选机构 |
| standardIds / standardNames | 接入方案多选；空数组=全部 |
| supplierIds / supplierNames | 供数方多选；空数组=全部 |
| channelType / httpConfig / mqConfig | 通道 |
| pushMode / scheduleType / cronExpr / intervalMinutes / batchLimit | 策略 |
| stats.successTotal / failTotal / lastPushCount / lastPushAt / backlog | 运行统计 |
| updatedAt | 更新时间 |

### 4.2 数据流（逻辑）

```
已入库数据
  → 按方案数据范围过滤
  → 按增量水位或全量快照取数
  → 按 batchLimit 分批
  → HTTP 外呼 / MQ 投递
  → 更新方案 stats
```

### 4.3 下线实体

- `OrgPushTask` 及「每机构每通道类型唯一」约束随任务模块一并废弃；唯一性改为方案名称全局唯一（保留）。

## 五、边界情况处理

1. **机构未选**：步骤 2 不可进入下一步。
2. **接入方案 / 供数方未选**：视为该机构下对应维度全部已入库数据。
3. **文件通道**：选项展示但禁用，提示本期不支持。
4. **停用方案**：立即停止调度；统计保留历史值。
5. **名称冲突**：保存失败并提示已存在同名方案。
6. **Cron / 间隔非法**：步骤 3 校验不通过不可提交。
7. **机构变更**：编辑时更换机构应清空或提示重新确认接入方案/供数方选择（避免跨机构脏数据）。
8. **统计**：原型为 mock 演示值；不承诺与真实入库账一致。
9. **权限**：本期运营角色可配置全部方案；细粒度机构权限后续迭代。
