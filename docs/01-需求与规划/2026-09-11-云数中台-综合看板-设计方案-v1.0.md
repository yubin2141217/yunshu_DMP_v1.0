# 云数中台 · 综合看板设计方案

## 一、项目概述

### 1.1 背景

云数中台运营管理系统现有「综合看板」以**数据接入**为主：按机构 / 接入方案 / 供数方筛选，展示接入总量、堆积量及分维度图表。数据推送（对外）能力已在「推送方案管理」落地，但方案级成功/失败/积压等整体分析尚未进入总览；既有设计文档亦约定外推量级与成功率等应归入数据概览 / 综合看板。

### 1.2 目标

- 将**接入（Inbound）**与**推送（Outbound）**纳入同一运营总览，形成「进得来、推得出」的一体视图。
- **汇报指标置顶、值班能力靠下**：服务管理层看吞吐与覆盖，同时服务运营排障。
- 与接入数据明细、推送数据明细、方案列表/详情形成可下钻闭环。
- 参考业界（API 网关 / 集成平台）常用 **吞吐、成功率、积压、错误 Top**，控制一期范围，避免虚高可观测性承诺。

### 1.3 核心价值

| 角色 | 价值 |
|------|------|
| 平台运营（汇报） | 同一时间窗对比接入量与推送成功量、方案规模与积压 |
| 平台运营（值班） | 失败/积压 Top、近 24h 失败趋势、启用方案零接入提示 |
| 产品/研发 | 口径与信息架构清晰，便于原型与后续真实指标落地 |

### 1.4 本期范围边界

| 纳入本期 | 明确不做（二期或更晚） |
|----------|------------------------|
| Tab：总览 / 接入 / 推送 | 环比 / 同比 |
| 总览汇报 KPI + 值班区（标准档） | 推送/接入延迟分位、SLO、告警规则引擎 |
| 公共筛选 + 按 Tab 扩展维度 | 多租户隔离视图、自定义看板 |
| 跳转明细与方案详情 | 单条报文级下钻（高基数） |

## 二、功能范围

### 2.1 模块清单

| 模块 | 优先级 | 说明 |
|------|--------|------|
| 公共筛选条 | 🔴 | 时间跨度、机构（多选）；查询 / 重置 / 刷新 |
| Tab · 总览 | 🔴 | 汇报 KPI 置顶 + 值班区靠下 |
| Tab · 接入 | 🔴 | 迁入并细化现有接入分析 |
| Tab · 推送 | 🔴 | 新增对外推送分析 |
| 下钻跳转 | 🟡 | KPI / TopN / 表格行 → 明细或方案详情 |
| 环比同比 / 延迟 SLO / 告警 | ⚪ | 二期 |

### 2.2 信息架构

```
综合看板
├── 公共筛选：时间跨度、机构
├── Tab「总览」：汇报 KPI → 值班区
├── Tab「接入」：接入 KPI → 趋势 → 三维图 → 组合明细
└── Tab「推送」：推送 KPI → 趋势 → 维度图 → 方案明细
```

### 2.3 筛选策略

| 作用域 | 筛选项 |
|--------|--------|
| 公共（三 Tab 共享） | 时间跨度、机构（多选） |
| 仅接入 Tab | 接入方案、供数方 |
| 仅推送 Tab | 推送方案 |
| 总览 Tab | 无额外筛选项（仅公共） |

### 2.4 总览汇报 KPI（本期固定）

| 指标 | 口径要点 |
|------|----------|
| 接入总量 | 公共筛选下累计接入条数 |
| 推送成功量 | 公共筛选下累计推送成功条数 |
| 推送成功率 | 成功 / (成功+失败)；无流量显示「—」 |
| 接入方案数 | 范围内有流量或启用的接入方案数（文案注明口径） |
| 推送方案数 | 范围内启用或有推送记录的方案数 |
| 待推积压 | 范围内各推送方案 backlog 合计 |

### 2.5 总览值班区（标准档）

1. 链路对照：接入总量 vs 推送成功量（同筛选时间窗；不强制因果）
2. 推送失败 TopN（按推送方案）
3. 待推积压 TopN（按推送方案）
4. 近 24h 失败趋势（**固定近 24h**，不受汇报时间窗改写）
5. 接入异常提示：启用中且近 1 日接入量为 0 的接入方案

### 2.6 业界对照与采纳

| 业界常见做法 | 本期采纳 |
|--------------|----------|
| Inbound / Outbound 分视图 | Tab 分栏 |
| Rate + Errors（成功率） | 总览成功率 + 失败 Top |
| Duration / 延迟分位 | 二期 |
| 积压单独监控 | 待推积压 KPI + TopN |
| 控制下钻基数 | 到方案/机构，明细另页 |

## 三、核心模块设计

### 3.1 公共筛选与 Tab

- 时间跨度：与现网一致（今日 / 近 3 天 / 近 1 周 / 近 1 月 / 累计等）。
- 机构：多选；空=全部。推送侧按推送方案 `orgId` 过滤。
- 切换 Tab **保留**公共筛选；Tab 专属筛选项仅在对应 Tab 生效与展示。
- 查询 / 重置 / 刷新：重置清空公共与当前 Tab 专属筛选并恢复默认时间跨度。

### 3.2 Tab「总览」

**布局（自上而下）**

1. 汇报 KPI 行（§2.4）
2. 值班区标题分隔
3. 链路对照卡 + 近 24h 失败趋势图（并排）
4. 失败 TopN、积压 TopN、接入零流量提示（表格或列表）

**交互**

| 元素 | 行为 |
|------|------|
| 接入总量 | 跳转「接入数据明细」，带时间与机构 |
| 推送成功量 / 成功率相关 | 跳转「推送数据明细」或推送方案列表 |
| 失败/积压 TopN 行 | 跳转对应推送方案详情 |
| 零接入提示行 | 跳转对应接入方案（详情或列表定位） |

**线框**

```
[时间] [机构]              [查询][重置][刷新]
[总览] [接入] [推送]

┌ 接入总量 │ 推送成功 │ 成功率 │ 接入方案数 │ 推送方案数 │ 积压 ┐
└────────────────────────────────────────────────────────────┘

── 值班 ──
┌ 链路对照 ┐  ┌ 近24h失败趋势 ┐
└──────────┘  └───────────────┘
┌ 失败TopN ┐ ┌ 积压TopN ┐ ┌ 接入零流量 ┐
└──────────┘ └──────────┘ └────────────┘
```

### 3.3 Tab「接入」

在现有综合看板能力上迁入并文案澄清：

- KPI：接入总量、当前堆积（待消费/待处理）、覆盖机构数、供数方数
- 趋势图：接入量与堆积量随时间
- 三维图：按机构 / 接入方案 / 供数方
- 组合明细表：机构 × 接入方案 × 供数方；支持跳转接入数据明细

专属筛选：接入方案、供数方（叠加公共时间与机构）。

### 3.4 Tab「推送」

与接入 Tab 对称：

- KPI：推送成功量、失败量、成功率、待推积压、启用推送方案数
- 趋势：成功/失败随时间（受公共时间窗）
- 维度：按机构、按推送方案；可选按通道类型（HTTP / MQ）分组
- 明细表：方案、机构、成功、失败、积压、最近推送时间；操作：详情、推送数据明细

专属筛选：推送方案。

### 3.5 视觉与交互原则

- 汇报区与值班区用分隔标题区分，避免 KPI 与 TopN 视觉权重颠倒。
- 成功率无流量显示「—」，不用 0% 误导。
- 图表与表格遵循现网 Arco + ECharts 风格，不新开设计体系。

## 四、数据结构与流向

### 4.1 逻辑实体与字段来源

| 实体 / 视图 | 主要字段 | 来源 |
|-------------|----------|------|
| 接入统计切片 | orgId, standardId, supplierId, inboundCount, backlog, timeBucket | 接入方案 accessStats / 现有 Stats Mock |
| 推送方案统计 | schemeId, orgId, successTotal, failTotal, backlog, lastPushAt | PushScheme.stats |
| 总览聚合视图 | inboundTotal, pushSuccess, pushFail, successRate, schemeCounts, backlogSum | 对上述切片按筛选聚合 |
| TopN 行 | id, name, metricValue | 推送方案或接入方案排序截断 |
| 零接入告警行 | standardId, name, lastAccessAt? | 启用接入方案 ∩ 近 1 日 inbound=0 |

### 4.2 数据流（逻辑）

```
接入侧明细/方案统计 ──┐
                      ├─→ 公共筛选（时间×机构）─→ 总览 KPI / 值班区
推送方案 stats ───────┘         │
                                ├─→ +接入方案/供数方 → 接入 Tab
                                └─→ +推送方案       → 推送 Tab

用户点击 KPI / TopN / 表格
  → 接入数据明细 / 推送数据明细 / 方案详情（带 query 参数）
```

### 4.3 口径约定

| 项 | 约定 |
|----|------|
| 推送成功率 | success / (success + fail)；分母为 0 → 「—」 |
| 机构过滤推送 | 匹配 PushScheme.orgId |
| 值班失败趋势时间 | 固定近 24 小时，独立于汇报时间跨度 |
| 链路对照 | 同公共时间窗下的接入总量与推送成功量并列；不作强因果断言 |
| 原型阶段 | 允许 Mock 聚合；字段命名与上表对齐便于换真接口 |

## 五、边界情况处理

### 5.1 空态与异常展示

| 场景 | 处理 |
|------|------|
| 筛选无任何接入/推送数据 | KPI 为 0 或「—」；图表空态文案；TopN 显示「暂无数据」 |
| 仅有接入无推送（或相反） | 对应侧为 0／—；链路对照仍展示两侧数字 |
| 成功率分母为 0 | 显示「—」，不显示 0% |
| TopN 不足 N 条 | 按实际条数展示 |
| 无启用方案触发零接入规则 | 零流量提示区空态 |

### 5.2 筛选与时间冲突

- 汇报区遵循公共「时间跨度」。
- 值班「近 24h 失败趋势」固定近 24h；可在图旁注明，避免与汇报窗混淆。
- 切换 Tab 不丢失公共筛选；专属筛选在离开 Tab 后可保留缓存或清空——**本期约定：保留至重置或离开综合看板页**。

### 5.3 权限与安全

- 与现运营工作台一致，不新增角色。
- 不下钻到单条正文/URL 列表（高基数、隐私风险）；明细能力复用已有明细页。

### 5.4 性能（原型与真接口预期）

- 总览聚合接口建议一次返回 KPI + TopN + 趋势点，避免瀑布请求。
- TopN 默认 5～10；明细表分页。
- 真接口阶段应对机构×方案高基数做服务端聚合，禁止前端拉全量明细再算。
