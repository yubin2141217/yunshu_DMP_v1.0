# 云数中台V8机构端数据概览扩充设计方案

## 一、项目概述

V8 机构端（mt-web `src/v8`）「数据概览」（`/v8/overview`，[Overview/index.vue](file:///d:/workrelated/trae/云数中台v1.0/mt-web/src/v8/views/Overview/index.vue)）当前为「6 张 KPI 卡 + 近7日入库趋势 + 推送成功率环形图 + 异常待办列表」的薄首页，大量已有数据资产（供方健康态、拒收原因、推送批次/回执/耗时、告警分类、机构配额、来源站点等）未在首页聚合。

本次将其扩充为机构值班人员的**运营驾驶舱**：核数量 → 看接入质量 → 对推送账 → 盯待办 → 知运营余量。

**核心价值**：一屏完成接入质量定位、推送对账、当日待办处置入口，减少在各模块间来回切换。

**红线不变**：仅展示统计与条目索引，不展示舆情正文；所有数据强制走当前用户 `supplierScope` 供方范围过滤；概览页只读，不放置任何写操作。

## 二、功能范围

| 序号 | 分区 | 模块 |
|---|---|---|
| 1 | 核心指标 | 现有 6 KPI 卡（口径标注微调，保留下钻） |
| 2 | 接入分析 | 拒收原因分布、供方入库量 TOP 榜、供方健康分布、24h 分时入库曲线 |
| 3 | 推送对账 | 推送批次指标条、推送量/成功率趋势、推送失败原因、最近推送批次 |
| 4 | 待办动态 | 待办聚合卡（告警/消息/回执）、告警类型分布、最近入库动态 |
| 5 | 运营概览 | 机构配额用量、接入规范版本、来源站点分布 TOP |
| 6 | 全局 | 页头时间范围切换（今日/近7天/近30天，默认近7天） |

## 三、核心模块设计

### 3.1 全局筛选

- 页头右侧新增时间范围单选按钮组：今日 / 近7天（默认）/ 近30天。
- 联动范围：除「24h 分时入库曲线」（固定近24h）、「推送成功率（24h）KPI」「待办/告警（实时口径）」「最近动态（固定近 N 条）」「运营概览（静态/累计口径）」外，其余统计随时间范围重算。
- 保留页头右上迷你统计：供数方数、入库总量、最近入库时间。

### 3.2 分区① 核心指标

保留现有 6 张卡与点击跳转：已配置供数方（→供数方查看）、入库总条数（→供数统计，副：今日量+环比）、今日拒收率（→供数统计）、供给健康度（→供数方查看）、推送成功率 24h（→推送回流）、异常待办（→供给监控）。无供方权限时整页空态「暂未分配供数方，请联系机构管理员在『用户与数据权限』中配置」。

### 3.3 分区② 接入分析（2×2 栅格）

| 模块 | 展示 | 交互/数据来源 |
|---|---|---|
| 拒收原因分布 | 环形图 + 图例（数量、占比） | 复用 6 类拒收原因：接入方案停用/AppKey 无效/IP 不在白名单/字段缺失或非法/数据归属不符/其他；点击区块或图例跳转供数统计并带 `result=reject`；零拒收时灰色「暂无拒收」占位 |
| 供方入库量 TOP 榜 | 横向柱状图，默认 TOP 8 | 按所选时间范围汇总各供方入库量降序；悬浮展示供方名、入库量、拒收量；点击柱条跳转入库数据核对并带供方 |
| 供方健康分布 | 健康/关注/异常/停用 四态环图 + 各态数量 | 复用 `healthMeta`；点击「关注/异常」跳转供数方查看并带 `health` 筛选 |
| 24h 分时入库曲线 | 当日 24 时点双系列折线（入库、拒收） | 固定近 24h，不受全局时间范围影响；用于定位断流/延迟时段 |

### 3.4 分区③ 推送对账

- **推送批次指标条**（6 个小卡）：推送批次总数、成功条数、失败条数、待回执批次数（橙）、平均推送耗时（批次 costMs 均值，秒）、重试次数合计。
- **推送量/成功率趋势**：近 7 天主柱（推送量）+ 折线（成功率%）双轴组合图，随全局时间范围。
- **推送失败原因**：横向条形图，聚合各批次 `failReasons`。
- **最近推送批次**：精简表，列为批次号、推送时间、方案、成功/失败、回执状态（已回执/未回执 Tag）、耗时、重试；取最近 5 条；右上「推送回流 →」跳 `/v8/pushback`。

### 3.5 分区④ 待办动态

- **待办聚合卡**（3 张大卡）：待处置告警（红，status=pending 计数，→供给监控）、未读消息（蓝，isRead=false 计数，→站内消息）、待回执批次（橙，receiptStatus=waiting 计数，→推送回流）；计数为 0 时显示绿色「无待办」。
- **告警类型分布**：供数断流、拒收率突增、入库延迟、字段异常 4 类待处理数量，迷你色块/柱条列表；点击跳供给监控并带 `type`。
- **最近入库动态**：时间流，每条仅供方名 + 入库时间 + 标题索引（DataEntry.title，不含正文），最多 8 条；右上跳入库数据核对。

### 3.6 分区⑤ 运营概览

- **机构配额用量**：`usedQuota/totalQuota` 进度条，≥80% 橙、≥95% 红；副文案「已用 X / 共 Y」；只读。
- **接入规范版本**：当前 active 版本号、发布时间、生效状态 Tag；「查看规范」按钮跳接入规范。
- **来源站点分布 TOP**：按 DataEntry.sourceSite 聚合 TOP 6 横向条形。

## 四、数据结构与流向

扩展 `Overview` 接口（[types.ts](file:///d:/workrelated/trae/云数中台v1.0/mt-web/src/v8/mock/types.ts)），由 `v8Service.overview(scope, range)` 一次性聚合返回，派生自现有 suppliers / alerts / pushBatches / entries / spec / orgInfo mock：

```ts
interface Overview {
  // 既有
  supplierCount: number
  inboundTotal: number
  lastInboundAt: string
  todayCount: number
  yesterdayCount: number
  todayRejectRate: number
  healthRate: number
  pushSuccessRate: number
  pendingAlertCount: number
  trend: OverviewTrendPoint[]
  // 新增：接入分析
  rejectReasons: { reason: RejectReason; count: number }[]
  topSuppliers: { supplierId: string; supplierName: string; inbound: number; reject: number }[]
  healthDist: Record<Health, number>
  hourlyTrend: { hour: string; inbound: number; reject: number }[] // 24 点
  // 新增：推送对账
  pushSummary: { batchCount: number; success: number; fail: number; waitingReceipt: number; avgCostMs: number; retryCount: number }
  pushTrend: { date: string; pushed: number; successRate: number }[]
  pushFailReasons: { reason: string; count: number }[]
  recentBatches: PushBatch[] // 最近 5 条
  // 新增：待办动态
  todoSummary: { pendingAlert: number; unreadMessage: number; waitingReceipt: number }
  alertTypeDist: Record<AlertType, number>
  recentEntries: DataEntry[] // 最近 8 条索引
  // 新增：运营概览
  quota: { used: number; total: number }
  activeSpec: { version: string; publishedAt: string; status: 'active' }
  siteDist: { site: string; count: number }[]
}
```

数据流：`Overview/index.vue → getOverview(range) → v8Service.overview(currentScope(), range)`，`currentScope()` 注入供方数据范围；下钻通过路由 query 携带供方/结果/类型/range 回填目标页。

## 五、边界情况处理

1. 无供方权限：维持整页空态，不展示任何统计。
2. 各图表无数据：统一灰色占位/`a-empty`，不抛错；拒收/推送失败为 0 时显示「暂无拒收」「暂无失败」。
3. 只读原则：概览页不放配置/处置类写操作，处置一律跳转对应模块完成。
4. 下钻参数：供方/结果/类型/range 经路由 query 透传，目标页自动回填并查询。
5. 视觉与依赖：沿用 v8 既有 `content-card`、`section-title`、`V8Chart` 组件与语义色（绿成功/红失败/橙警告/灰默认），不引入新依赖；纵向分区滚动，栅格响应式（xs/sm/lg/xl）。
