# 云数中台 V8 机构端设计方案

## 一、项目概述

### 1.1 背景

云数中台是面向多供数厂商、多机构的舆情数据汇聚与核验平台，产品分为两个端：

- **MT 管理端**：我司后台运营管理人员使用，拥有全部配置权（供数方、IP 白名单、字段库、接入方案、推送方案、机构授权等），功能内容已在 mt-web 工程中基本确定。
- **V8 机构端**：租户机构（网信、网安等政府机构客户）使用的 PC Web 端，数据严格按机构隔离，本期对其功能进行系统性扩展。

此前 SRS V1.7/V1.8 与 0920 PRD 将 V8 机构端限定为"保持既有、只核验不配置"，仅含数据概览、供数统计、供数方查看、接入规范 4 个菜单。本方案在不改变中台"数据通道 + 核验 + 计量"本质的前提下，结合 MT 端已实现能力、政府机构对舆情数据"查看管控"的真实业务场景与竞品（蚁坊、拓尔思、百分点、中科闻歌等）共性，对 V8 机构端做一次**主动扩展立项**。

### 1.2 目标

让机构用户从"只看入库统计数字"升级为"**核数量 → 对条目 → 管异常 → 可溯源 → 能留痕**"，具体目标：

1. 能按供数方核对入库量与明细，并可通过原文链接溯源到来源系统；
2. 对"供数方 → 中台"的数据供给做通道级监控与主动告警，保障 7×24 不断供；
3. 掌握"中台 → 本机构接收端"的推送回流结果，便于对账与催办；
4. 通过微信扫码准入 + 菜单/供数方数据权限双重控制，满足等保三级与机构内部分级查看要求；
5. 全程不越界做舆情正文研判，保持与专业舆情应用的职责边界。

### 1.3 目标用户

| 角色 | 典型用户 | 核心诉求 |
| --- | --- | --- |
| 机构管理员 | 网信办/网安信息化负责人 | 管本机构用户与数据权限、掌握供给与推送全局、异常处置、合规留痕 |
| 数据值班/核对人员 | 机构数据值守岗 | 每日核对各供数方入库量、发现断供/拒收异常、对账留痕 |
| 只读查看人员 | 机构内仅需查看的人员 | 在被授权的菜单与供数方范围内查看数据 |

### 1.4 核心定位与边界

- **是**：按机构隔离的"数据汇聚核验门户"，管数据"有没有、到没到、到了多少、来自哪个供方、推没推成功"。
- **不是**：舆情研判工作台、行业应用前台、开放数据市场。
- **正文边界（本次确认口径 C）**：
  - 可查看条目的**内容标题**及供数方、发布时间、作者、接入时间、来源 URL 等索引字段；
  - 可点击 **URL 新窗口外链**到来源系统/供数方平台阅读全文，跳转前给出"即将离开云数中台"二次确认；
  - **不在**云数中台落地展示、存储正文全文，不做正文全文检索与语义分析。
- **配置权边界**：全部配置（供方、白名单、字段库、接入/推送方案、机构授权、告警基准阈值）在 MT；V8 为"只读 + 对外协同动作"（下载规范转交厂商、订阅告警、确认处置告警、外链溯源）。
- **权限边界**：登录后强机构隔离，仅本机构数据；仅计入"供方启用 + 本机构已配置（有开启接入方案）"的数据。

## 二、功能范围

### 2.1 功能模块全景（12 个模块）

| # | 模块 | 现状 | 本期动作 |
| --- | --- | --- | --- |
| 01 | 微信扫码登录与会话 | 现为账密登录 | 改造为微信扫码样式登录（原型点击二维码进入） |
| 02 | 数据概览（工作台） | 已有 3 指标 | 增强：健康度、今日量/环比、拒收率、推送概况、异常待办、趋势 |

| 07 | 推送回流查看 | 无 | 新增（只读）：推送概况 + 失败/积压明细 |

| 09 | 消息/通知中心 | 无 | 新增：承接供给告警、授权到期、规范更新、系统通知 |

### 2.2 优先级分期

- 🔴 **P0（本期必做）**：微信扫码样式登录；数据概览增强（健康度、今日量/环比、异常待办）；供数统计基础增强；**入库数据核对（标题 + 外链）**；供数方查看；**供给监控告警闭环（看板异常 + 站内信 + 订阅开关/接收人 + 处置留痕）**；消息中心；用户与数据权限管理。
- 🟡 **P1（本期建议）**：拒收统计与原因分布、统计/条目导出、推送回流查看、接入规范版本化与字段口径、机构与授权信息、操作/登录审计留痕、个人设置、告警多通道扩展（短信/邮件）。
- ⚪ **P2（远期预留）**：统一认证中心 SSO/RBAC 正式对接、推送趋势图、审计日志导出、条目导出等。

### 2.3 关键决策口径（本次讨论确认）

1. **正文**：放开标题与 URL 外链，正文不在中台落地展示/检索/分析。
2. **登录**：仅微信扫码样式；原型阶段不接真实认证，点击二维码即模拟登录进入，后续替换为真实扫码回调，样式不变。
3. **用户来源**：机构用户统一走公司已有微信扫码认证流程添加，V8 端不手工建号。
4. **数据权限粒度**：双重控制——可访问菜单模块 + 可见供数方数据范围；权限点字典由 V8 应用集成中心下发，中台不自建。
5. **告警阈值**：MT 统一制定基准，机构不可改阈值，仅可订阅告警开关、级别、接收人。
6. **拒收可见度**：机构端仅看供方维度拒收统计与拒收原因分布；拒收不落库、无条目级数据。
7. **告警通道**：本期 = 看板异常展示 + 站内消息中心；短信/邮件等作为消息通知扩展通道预留。
8. **推送**：机构作为接收方只读查看结果，无任何推送方案配置入口。

## 三、核心模块设计

### 3.1 模块 01：微信扫码登录与会话

**功能说明**

- 登录页保留并改造现有浅蓝气泡视觉，主登录区呈现**微信扫码二维码**样式，配"请使用微信扫码登录"提示。
- 原型阶段：**不接真实微信认证，点击二维码即模拟登录成功**进入业务首页（携带 redirect 回跳）；二维码下方可放"点击二维码模拟登录"的弱提示，便于演示验收。
- 后续正式对接：将"点击"行为替换为公司微信扫码认证的扫码状态轮询/回调，页面结构与样式不变。
- 未登录不可进入任何业务页，由独立 V8 路由守卫拦截，跳转扫码登录页并带回跳地址。
- 退出登录清除本端会话，回到扫码页。

**交互逻辑**

1. 用户访问任意 `/v8/*` 业务页 → 无会话则跳 `/v8/login?redirect=...`。
2. 点击二维码（原型）→ 写入演示机构会话（绑定一个演示机构 + 机构管理员权限）→ 跳转 redirect 或 `/v8/overview`。
3. 点右上角退出 → 清会话 → 回扫码页。

**数据流向**：扫码（原型点击）→ 认证服务/原型 mock 返回用户身份与所属机构、权限点 → 写入 V8 用户会话（store，独立于 MT 的 user store）→ 菜单与供方数据按权限渲染。

### 3.2 模块 11：用户与数据权限管理

**功能说明**

- **用户列表**：展示本机构下经微信扫码认证纳入的用户（头像、微信昵称/姓名、加入时间、状态）；**端内不提供手工新增账号入口**，新成员通过扫码认证流程加入。
- **编辑数据权限（双重控制）**：
  1. **菜单模块权限**：勾选该用户可访问的模块（数据概览、供数统计、入库核对、供给监控、推送回流、接入规范等）；
  2. **供数方数据范围**：勾选该用户可见的供数方（如仅允许看 A 厂商），未勾选供方的数据在所有统计、条目、看板中对其不可见。
- **权限点来源**：可勾选的菜单项与供数方候选由 **V8 应用集成中心下发/同步**；云数中台只负责读取与回配，不自建权限字典、不自定义权限项。
- 仅机构管理员可见本模块；只读查看人员无入口。

**交互逻辑**

1. 机构管理员进入"用户与数据权限"→ 看到本机构用户列表（来自扫码准入 + 集成中心同步）。
2. 点某用户"编辑权限"→ 抽屉中两组勾选：菜单模块 / 供数方范围。
3. 保存 → 回写集成中心（原型为本地 mock）→ 该用户下次请求/刷新后按新权限生效。
4. 用户状态（启用/停用）随集成中心，V8 端只读展示或有限启停（以集成中心能力为准）。

**数据流向**：集成中心权限点字典 → V8 权限编辑界面；编辑结果 → 集成中心持久化（原型 mock）→ 接口请求携带用户与机构上下文 → 后端按"菜单 + 供方"过滤数据。

**边界**：机构开通、组织主数据、账号认证本体均在 V8 集成中心/微信认证体系，云数中台不重复建设；本模块只做"本机构用户的查看 + 数据权限分配"。

### 3.3 模块 02：数据概览（工作台）

**功能说明**

登录后首页，一屏掌握本机构供给与推送健康状态。在现有"已配置供数方数 / 入库总条数 / 最近入库时间"3 项指标基础上增强：

- **供给健康度灯号**：按供数方显示正常（绿）/ 断供（红）/ 异常（黄），点击进入监控告警对应供方。
- **今日入库量 + 环比**：当日新增条数，与昨日同时段对比涨跌（百分比 + 上下箭头）。
- **入库总条数 / 最近入库时间**：保留现有口径（累计含停用供方历史数据；无数据显示 0 / "暂无入库"）。
- **拒收率（P1）**：统计周期内拒收条数占比，仅供方维度数值，不提供拒收条目。
- **推送概况（P1）**：中台→本机构接收端今日推送成功 / 失败 / 积压条数，失败可下钻推送回流明细。
- **异常待办区（P0）**：列出未处理的断供/异常告警与推送失败 Top，点击直达处置或明细。
- **入库趋势迷你图（P1）**：近 7/30 天按日入库曲线，断供时段以红色区段直观标注。
- **快捷入口**：供数统计、入库数据核对、接入规范（沿用现有）。

**数据流向**：概览聚合接口按"机构 + 当前用户供方数据权限"返回指标；健康度/异常来自监控引擎判定结果；推送概况来自 MT 推送记录按本机构过滤。

### 3.4 模块 03：供数统计

**功能说明**

- 按供数方核验入库条数，时间范围全部 / 近 7 天 / 近 30 天，默认全部（按到达中台时间），分页默认 10 条；未配置供方不出现，已配置未入库显示 0。
- **入库量趋势（P1）**：按日折线/柱状，支持多供方叠加对比。
- **拒收统计（P1）**：各供方拒收条数与拒收率，并用分布图展示拒收原因（AppKey 鉴权失败 / IP 白名单不命中 / 字段校验失败 / 无法归属机构）。
- **多维筛选（P1）**：供数方、时间范围、供给状态。
- **导出对账单（P1）**：导出 Excel（供方、周期、入库量、拒收量、拒收率），用于机构内部对账与报送留痕。
- 全程仅统计数字，不展示任何舆情条目正文。

**边界**：拒收数据不落库，机构端只可见聚合统计与原因分布，无法下钻到"被拒收的是哪一条"。

### 3.5 模块 04：入库数据核对（口径 C 核心，新增）

**功能说明**

机构对本机构已入库数据做条目级核对与溯源，是本次从"看数字"到"对条目"的关键模块。

- **条目列表（P0）**：按接入时间倒序分页，仅本机构、且在当前用户供方数据权限内的条目。
- **展示索引字段（P0）**：内容标题、供数方、发布时间、作者昵称、接入时间、来源 URL。
- **原文外链溯源（P0）**：点击 URL 弹出"您即将离开云数中台，前往第三方来源系统，请注意信息安全"二次确认，确认后**新浏览器标签页**打开来源地址；云数中台页面内不渲染正文。
- **筛选（P0）**：按内容标题、供数方、发布时间/接入时间区间检索，用于与供数方对账、定位某天数据。
- **条目详情抽屉（P1）**：展示完整元数据与中台打标（接入方案、归属机构、供数方、接入时间、来源 URL），不含正文字段。
- **条目导出（P2）**：导出当前筛选结果的索引字段（明确不含正文）。

**数据流向**：中台已入库且按机构打标的条目 → 经"供方启用 + 本机构已配置 + 当前用户供方权限"三重过滤 → 返回索引字段列表；正文 `content` 字段在接口与前端两层均不下发、不渲染；阅读全文仅通过外链跳出。

### 3.6 模块 05：供数方查看

**功能说明**

- 保留现有**只读名单**：供数方名称 + 启用/停用状态，不可新增/编辑/删除；空态"尚未配置供数方，请联系平台运营"。
- 停用供方：仍在列表展示并标注停用，其历史入库数据保留可统计。
- **供方详情弹层（P1）**：该供方今日/累计入库量、最近入库时间、当前健康状态、近 7 天趋势缩略图。
- 供方主数据与启停由 MT 维护，V8 为随主数据联动的只读投影。

### 3.7 模块 06：供给监控与告警（网信特色，新增）

对"**供数方 → 中台**"的数据供给通道本身做监控，监控的是数据供给状态，**不是舆情内容**。

**监控类型**

- **断供监测（P0）**：某供方连续 N 小时无入库即判异常（N 由 MT 统一设定基准）。
- **量值异常（P1）**：入库量骤降/骤增超过 MT 设定的环比/同比阈值。
- **拒收率异常（P1）**：某供方拒收率超过阈值。

**功能点**

- **异常规则查看（P1）**：机构可查看本机构生效的监控项与阈值（只读，阈值由 MT 定，机构不可改）。
- **告警记录列表（P0）**：时间、供数方、异常类型、级别、当前状态（待处理/已确认/已恢复），支持按供方、类型、状态、时间筛选。
- **告警确认与处置（P0）**：值班人可"确认/标记处理中/已解决"，并填写处置说明，形成闭环留痕（确认人、时间、说明）。
- **订阅设置（P0）**：机构为每类/每供方告警设置开关、最低级别、**接收人**（本机构用户）；阈值不可改。
- **触达渠道**：本期为看板灯号/待办 + **站内消息中心**；短信、邮件等消息通知通道作为扩展预留，按公司通道能力开通。

**交互逻辑**：监控引擎按 MT 基准规则扫描 → 命中生成告警 → 依订阅写入对应用户站内信、更新看板灯号与待办 → 值班人确认处置、状态流转直至恢复 → 全流程留痕。

### 3.8 模块 07：推送回流查看（新增，只读）

机构作为数据接收方，掌握"中台 → 本机构接收端"这后半段的流转结果；**无任何推送方案配置入口**。

- **推送概况（P1）**：累计/今日推送量、成功、失败、积压条数。
- **失败/积压明细（P1）**：条目级列表——内容标题、目标接收端、失败原因、重试状态/次数、最近推送时间；支持按状态、时间筛选。
- **催办引导**：对持续失败/积压项提供"联系平台运营核查"提示（不直接暴露 MT 配置）。
- **推送趋势图（P2）**：成功 vs 失败按日曲线。
- 数据来自 MT 推送记录，按本机构过滤，机构只读。

### 3.9 模块 09：消息/通知中心（新增）

- **站内消息列表（P0）**：类型含供给异常告警、推送失败、授权到期提醒、接入规范更新、系统通知；未读优先、按类型/时间筛选。
- **未读角标（P0）**：顶栏铃铛展示未读数，点击进入消息中心。
- **已读管理（P0）**：单条已读、全部已读；告警类消息可一键跳转对应告警处置页。
- **告警订阅设置（P0/P1）**：接收类型、最低级别、接收人；P1 扩展短信/邮件等通道开关（通道能力就绪后开放）。
- 消息中心是本期告警触达的主通道，所有异常与提醒统一在此收口。

### 3.10 模块 08：接入规范

在现有"查看/下载当前规范文件"基础上，对齐设计方案 v1.3"本机构生效标准"口径增强：

- **当前生效规范（P0）**：文件名、类型、大小、发布时间，可在线预览与下载，用于转交供数厂商按标准送数。
- **版本号与更新提示（P1）**：明确展示"本机构生效版本号"；规范被 MT 更新后，机构登录有更新提示并可查看更新时间（历史版本仅留版本记录，P2 评估是否可下载历史版）。
- **字段口径与识别规则（P1）**：页面内直接展示本机构生效的字段块（字段名/中文名/类型/必填）、接入方式（HTTP/HTTPS、接口路径/AppKey 说明）与字段识别规则说明，减少文档沟通成本。
- **转交引导（P0）**：一键复制下载地址或"联系平台运营获取"提示。
- **下载留痕（P2）**：记录谁在何时下载了哪个版本，服务于审计与报送。
- 规范的制定、上传、替换、字段库维护仍全部在 MT；机构只读与下载。

### 3.11 模块 10：机构与授权信息（新增，只读）

- **机构档案（P1）**：机构主名称、副信息（所属统计单元、对接销售）、统一社会信用代码等，数据来自机构主数据/V8 集成中心，只读。
- **授权信息（P1）**：授权版本、授权状态（正常/临期/过期/停用）、授权到期日。
- **到期提醒（P1）**：临期（如到期前 30/15/7 天）在消息中心与本页提醒，引导"联系平台运营续费"；过期后按授权策略限制访问（见边界处理）。
- 机构不可在本端修改档案或自助开通，所有变更联系运营在 MT/集成中心处理。

### 3.12 模块 12：个人设置

- **个人信息**：微信昵称/姓名、头像、所属机构（来自扫码认证与集成中心，只读为主）。
- **联系方式（P1）**：维护用于告警触达的手机号/邮箱（短信邮件通道就绪后生效）。
- **我的告警订阅（P0/P1）**：快捷查看/设置本人接收的告警类型、级别、渠道（与模块 09 订阅一致）。
- **退出登录**：清除会话回到扫码页。
- 修改密码等账密类能力在纯扫码模式下不适用，不提供。

## 四、数据结构与流向

### 4.1 关键数据实体（V8 视角）

| 实体 | 关键字段 | 来源 / 归属 |
| --- | --- | --- |
| V8 会话用户 | userId、机构 orgId、角色、菜单权限点、可见供方 id 列表 | 微信扫码认证 + V8 集成中心 |
| 机构 | orgId、名称、统一社会信用代码、统计单元、对接销售、授权版本/状态/到期日 | 机构主数据 / 集成中心，V8 只读 |
| 供数方（投影） | supplierId、名称、编码、启用状态、健康状态 | MT 主数据，按本机构关系过滤 |
| 入库条目（索引） | 条目 id、news_title、news_url、news_posttime、media_name、supplierId、orgId、方案 id、accessAt | 中台已入库打标数据；**不含 content 正文字段** |
| 入库/拒收统计 | supplierId、周期、入库量、拒收量、拒收率、拒收原因分布 | 中台按机构 + 供方聚合 |
| 告警规则（只读） | 监控类型、阈值基准、生效供方 | MT 制定下发 |
| 告警记录 | 告警 id、供方、类型、级别、状态、发生/恢复时间、处置人/说明 | 监控引擎生成，机构可处置 |
| 告警订阅 | 用户、告警类型、级别、开关、接收人 | 机构侧配置 |
| 推送记录 | 条目 id、目标接收端、状态（成功/失败/积压）、失败原因、重试次数/时间 | MT 推送记录，按本机构过滤只读 |
| 站内消息 | 消息 id、类型、标题、内容、已读状态、关联告警 id、时间 | 系统生成 |
| 接入规范 | 版本号、文件名/类型/大小、发布时间、字段块、接入方式 | MT 维护，V8 只读下载 |

### 4.2 核心数据流转

1. **准入与权限**：微信扫码 → 认证/集成中心返回用户、机构、菜单权限点、可见供方 → 会话生效 → 前端菜单与全部数据请求按此过滤。
2. **数据汇聚可见链路**：供数方送数 → MT 校验（方案状态/AppKey/IP 白名单/字段/归属）→ 通过则落库按机构与供方打标；不通过拒收计数（不落库）→ V8 概览/统计/核对在"本机构 + 有权供方"范围内只读呈现索引与聚合。
3. **正文溯源链路**：条目仅返回标题与 URL；用户点外链 → 二次确认 → 新标签跳转第三方来源阅读，正文不经过中台展示层。
4. **监控告警链路**：监控引擎按 MT 基准扫描入库流水 → 命中异常生成告警 → 按订阅写站内信、点灯号/待办 → 值班人确认处置 → 恢复闭环留痕。
5. **推送回流链路**：MT 推送方案把本机构已入库数据推送到机构接收端 → 推送结果记录 → V8 推送回流模块按本机构只读查看成功/失败/积压。
6. **规范下发链路**：MT 更新生效标准 → V8 接入规范展示新版本并提示 → 机构预览/下载转交供数厂商。

### 4.3 隔离与安全原则

- **机构隔离**：所有查询强制带 orgId，机构间数据物理/逻辑互不可见。
- **供方级数据权限**：在机构隔离之上再按用户"可见供方列表"二次过滤，作用于看板、统计、条目、告警、推送所有模块。
- **正文最小化**：接口不下发 content，前端不渲染；外链跳转做安全提示并新标签打开。
- **配置单向**：机构端对供方/方案/阈值/规范均只读，写操作仅限告警处置与告警订阅、本人订阅设置。
- **审计留痕**：登录、外链点击、规范下载、告警处置、导出等敏感动作记录操作日志（P1），支撑等保三级。

## 五、边界情况处理

| 场景 | 处理规则 |
| --- | --- |
| 未登录访问业务页 | 路由守卫拦截，跳扫码登录页并带回跳地址，登录后返回 |
| 扫码用户未归属任何机构 | 提示"未查询到所属机构，请联系平台运营开通"，不进入业务页 |
| 机构授权过期/被停用 | 登录后进入受限提示页，展示到期/停用原因与续费联系入口，不展示业务数据 |
| 用户无任何菜单权限 | 登录后展示空态"暂未分配功能权限，请联系机构管理员" |
| 用户供方数据范围为空 | 各统计/条目/看板均显示空态（0、暂无数据），不报错、不越权展示他人供方 |
| 供数方被 MT 停用 | 名单仍展示并标停用；历史数据保留可统计，停用后新数据不计入；监控可对停用供方静默 |
| 全部供方断供 | 概览健康度全红 + 顶栏高危告警 + 站内信；条目与统计显示无新增，保留历史 |
| 拒收数据 | 不落库、无条目；仅在统计模块以供方维度聚合计数与原因分布呈现 |
| 原文 URL 缺失/失效 | 外链按钮置灰或点击提示"来源链接不可用"；不在中台补抓正文 |
| 外链安全 | 统一"即将离开云数中台"二次确认，新标签打开，不带走中台登录态之外的敏感参数 |
| 告警重复/抖动 | 同一供方同一类型在未恢复周期内合并为一条告警，避免刷屏；恢复后再异常才新建 |
| 告警无人处置 | 超 SLA 未确认时升级提示（站内信置顶/提高级别），P1 可扩展短信邮件 |
| 推送持续失败/积压 | 回流模块高亮失败积压，提供联系运营核查引导，机构不可自行改推送配置 |
| 接入规范更新 | 新版本生效后登录提示更新；旧版本仅留版本记录（历史可下载性列 P2） |
| 权限点字典加载失败 | 权限编辑页只读降级并提示"权限服务暂不可用"，不允许在本地臆造权限项 |
| 原型扫码 | 点击二维码即模拟机构管理员登录；接真实微信认证时仅替换认证适配层，页面不变 |
