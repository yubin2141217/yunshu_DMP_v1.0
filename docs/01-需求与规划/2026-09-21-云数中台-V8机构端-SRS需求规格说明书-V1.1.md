## 1 引言

### 1.1 目的
定义云数中台 V8 机构端（网信/网安等政府租户机构使用的 PC Web 端）本期全部功能的页面、字段、业务规则、边界异常与数据字典，作为前端原型实现与验收的唯一规格真源。

### 1.2 范围
- 在既有「数据概览、供数统计、供数方查看、接入规范」4 菜单基础上，扩展为 12 个模块（见 3.1）。
- 主线：核数量 → 对条目 → 管异常 → 可溯源 → 能留痕。
- **不包含**：舆情正文全文落地展示/检索/语义分析；供数方、接入方案、推送方案、字段库、白名单、告警阈值基准等配置（均属 MT 端）。

### 1.3 正文口径（强约束）
机构端可见条目的**索引字段**（内容标题、供数方、发布时间、作者昵称、接入时间、来源 URL），可点 URL **新标签外链**到来源系统阅读（离开平台二次确认）；**正文 content 字段在类型、接口、前端三层均不下发、不渲染、不导出**。

### 1.4 通用约定（遵循康奈 V8 规范）
- 时间格式 `YYYY-MM-DD HH:mm:ss`；数值千分位；状态标签语义色：成功/通过/启用=绿，失败/错误=红，警告/待处理=橙，中性/已完成=灰，进行中/处理中=蓝。
- 列表：默认排序列；文本左对齐、序号/标签居中、金额/数值右对齐；操作列固定最右；长文本截断 Tooltip；分页默认 10 条/页，可选 10/50/100/200/500，显示总条数与页码省略；查询条件标签与表头一致。
- 交互容器：简单确认用居中模态，详情/复杂表单用右侧抽屉；外链原文新标签打开。
- 每个页面必须有加载态、初始空态、查询无结果空态、无权限/不存在/服务器错误异常页（按规范文案与引导按钮）。
- **水印（强制）**：V8 业务区全铺水印，内容为「用户名 · 手机尾号后四位 · 日期」。
- 顶栏（本期范围）：Logo/系统名「云数中台」/机构名标签/「机构端」标签 + 「MT管理端」入口 + 消息铃铛（未读角标）+ 头像（下拉仅「退出登录」）。下载中心、联系客户经理、帮助中心、个人中心、切换机构**本期不做**。

## 2 总体描述

### 2.1 用户角色
| 角色 | 权限 |
| --- | --- |
| 机构管理员 | 全部 12 模块可见；可在「用户与数据权限」编辑本机构用户的菜单 + 供方数据权限；可处置告警、改订阅 |
| 数据值班/核对员 | 概览、统计、入库核对、供数方、监控告警、消息、规范、推送回流等（由管理员勾选菜单与供方范围）；可处置被分配的告警 |
| 只读查看员 | 仅被授予模块的查看权；无用户管理、无告警处置写操作 |

### 2.2 运行环境
Chrome ≥91 / Edge ≥91 / Firefox ≥90，默认 1440×900，有效区 1320px，适配 1366~2560 宽度。

### 2.3 技术约束
- 强机构隔离（orgId）+ 用户供方数据范围二次过滤，作用于所有看板、统计、条目、告警、推送、消息。
- 用户与权限点来自微信扫码认证与 V8 应用集成中心（本期 Mock：登录页点击二维码模拟机构管理员登录；权限字典 Mock）。
- 全部数据来自 `src/v8/mock`，经 `src/v8/api` 返回 Promise；写操作（权限、订阅、告警处置、已读）在 Mock 内持久化。

### 3.1.2 导航与默认行为
- 登录成功默认进入 `/v8/overview`；若带合法 `redirect`（以 `/v8/` 开头且非协议相对）则回跳。
- 面包屑固定「我的工作台 / 当前菜单名」。
- 顶栏「MT管理端」→ `/stats`；消息铃铛 → `/v8/message`；头像「退出登录」→ 清会话回 `/v8/login`。
- 直接访问未授权路由：转 `/v8/restricted`（无权限态）；未登录：转 `/v8/login` 带回跳。

### 3.1.3 与 MT 的数据流关系
供数方送数 → MT 校验（方案状态/AppKey/IP白名单/字段/归属）→ 通过落库并按机构、供方打标；不通过计拒收（不落库）→ MT 推送方案把已入库数据推到机构接收端。V8 端在「本机构 + 有权供方」范围内只读消费上述结果，并可处置 MT 监控引擎产生的告警。

## 3.5 功能详细设计

> 通用：所有列表接口入参含 `orgId`（由会话注入，前端不暴露可编辑）；前端再按当前用户 `supplierScope` 二次过滤供方维度。时间统一 `YYYY-MM-DD HH:mm:ss`。正文 `content` 全链路不出现。

### P00 扫码登录
- 页面居中卡片：左品牌区/右二维码区（窄屏堆叠）。二维码区展示方形二维码占位（`/images` 或内联 SVG），下方文案「请使用微信扫码登录」与状态行。
- 扫码状态机：`waiting`（等待扫码，60s 倒计时）→ `scanned`（已扫码，请在微信确认）→ `confirmed`（登录中）/ `expired`（二维码已过期，点击刷新）。
- Mock 交互：点击二维码依次 `waiting→scanned→confirmed`（演示自动轮询），确认成功后以**机构管理员**身份建立 V8 会话（含全部菜单权限 + 全部供方范围），执行回跳逻辑。
- 提供低调「演示：一键以机构管理员登录」文字按钮（原型演示用，正式隐藏）。
- 不提供账号/密码、注册、忘记密码入口（既有账密登录整体替换）。
- 边界：二维码过期必须显式刷新；登录失败（如无机构归属）→ 转受限态「无机构」。
- 验收：点击二维码可走通三态并进入概览；刷新可重置倒计时；回跳参数受 `/v8/` 前缀校验。

### P01 数据概览【V1.1 扩充】

**整体**：默认落地页，纵向分区滚动的五分区运营驾驶舱；只读（无任何配置/处置写操作，处置一律跳转对应模块）；全页数据按「机构 + 当前用户 supplierScope」过滤；仅展示统计与条目索引，不出现正文 content。

**页头与全局筛选**

- 标题/说明 + 右侧全局时间范围单选：今日 / 近7天（默认）/ 近30天；切换后联动除 24h 分时、24h 推送成功率 KPI、待办/告警实时口径、最近动态、运营概览外的全部统计。
- 右上摘要：供数方数、入库总量、最近入库时间。

**分区① 核心指标（6 张 KPI 卡，均可点击下钻）**：①已配置供数方（→P04，副标含停用供方数）②入库总条数（副：今日量 + 环比昨日百分比，绿涨红降，→P02）③今日拒收率（拒收/总送数，超阈值标橙，→P02 且带拒收）④供给健康度（健康供方/总供方百分比 + 语义色，→P04）⑤推送成功率（近 24h，→P06）⑥异常待办数（待处置告警，→P05）。

**分区② 接入分析（2×2 栅格）**

- 拒收原因分布：环形图 + 图例（数量、占比），枚举同 6.1.11 RejectReason 六类；点击跳 P02 带 `result=reject`；零拒收显示「暂无拒收」。
- 供方入库量 TOP 榜：横向柱图，按全局时间范围汇总各供方入库量降序取 TOP 8；悬浮显供方名/入库量/拒收量；点击跳 P03 并带供方。
- 供方健康分布：健康/关注/异常/停用四态环图 + 各态计数（health 枚举同 6.1.4）；点击关注/异常跳 P04 带 `health`。
- 24h 分时入库曲线：固定近 24h 的 24 时点双系列折线（入库、拒收），不随全局时间范围变化。

**分区③ 推送对账**

- 批次指标条（6 小卡）：批次总数、成功条数、失败条数、待回执批次数（receiptStatus=waiting，橙）、平均推送耗时（costMs 均值，秒）、重试次数合计。
- 推送量/成功率趋势：随全局时间范围的推送量柱 + 成功率（%）折线双轴组合图。
- 推送失败原因：横向条图，聚合 PushBatch.failReasons（接收端超时/接口错误/数据格式/其他）。
- 最近推送批次：最近 5 条精简表，列＝批次号、推送时间、方案、成功/失败、回执状态（已回执/未回执 Tag）、耗时、重试；右上「推送回流 →」跳 P06。

**分区④ 待办动态**

- 待办聚合卡（3 张）：待处置告警（红，AlertRecord.status=pending 计数，→P05）、未读消息（蓝，V8Message.isRead=false 计数，→P07）、待回执批次（橙，→P06）；为 0 显示绿色「无待办」。
- 告警类型分布：断流/拒收率突增/延迟/字段异常四类（AlertType）待处理数量，点击跳 P05 带 `type`。
- 最近入库动态：时间流，每条仅供方名 + 入库时间 + 内容标题（DataEntry.title 索引，无正文），最多 8 条，右上跳 P03。

**分区⑤ 运营概览**

- 机构配额用量：OrgInfo.usedQuota/totalQuota 进度条，≥80% 橙、≥95% 红，副文案「已用 X / 共 Y」；只读。
- 接入规范版本：当前 active SpecVersion 的版本号、publishedAt、生效状态 Tag；「查看规范」跳 P08。
- 来源站点分布 TOP：按 DataEntry.sourceSite 聚合 TOP 6 横向条图。

**边界**：无任何供方权限 → 概览空态「暂未分配供数方，请联系机构管理员在『用户与数据权限』中配置」，不展示任何统计；任一区块数据缺失独立空态，不整页报错；拒收/失败为 0 分别显「暂无拒收」「暂无失败」；下钻统一经路由 query 透传供方/结果/类型/时间范围并在目标页回填。

### P02 供数统计
- 筛选：时间范围（近7天/近30天/自定义，默认近7天）、供数方（多选，仅范围内）、结果（全部/成功/拒收）；「查询」「重置」；右上角「导出」（按当前筛选，Mock 生成 CSV 下载并提示留痕）。
- 顶部汇总：总送数、成功入库、拒收、拒收率。
- 图表：入库/拒收趋势；拒收原因分布（饼图：方案停用/AppKey无效/IP不在白名单/字段缺失或非法/归属不符/其他）。
- 明细表（分页）：日期、供数方、送数总量、成功量、拒收件数、拒收率、主要拒收原因；数值右对齐。
- 边界：时间跨度上限 92 天，超限提示；导出超 5 万行提示「缩小范围」；查询无结果空态。

### P03 入库数据核对
- 筛选：关键词（匹配内容标题，不含正文）、供数方、作者昵称、发布时间范围、入库时间范围；查询/重置。
- 表格列（仅索引）：序号、内容标题（截断 Tooltip 显示全标题）、供数方、作者昵称、发布时间、入库时间、来源（URL 操作）、操作（查看/访问原文）。默认按入库时间倒序；分页 10。

### P12 受限态
- 三种情形复用同一结果页组件，按 `type` 区分：

### 3.5.x 全局非功能
- 水印：V8Layout 内容区全铺平铺水印（SVG 背景或定位层，`pointer-events:none`），文字 `${用户名}·${手机后四位}·${YYYY-MM-DD}`，透明度低、约 20° 旋转、覆盖滚动全高。
- 路由守卫三层：①未登录 → 登录回跳；②无机构/授权过期 → 受限态；③有会话但无目标菜单权限 → 受限态 forbidden。供方过滤在每个数据 api 的 Mock 层强制兜底。
- 加载/空/异常：列表使用统一骨架或 Spin；空态用 Arco Empty + 规范引导按钮；接口异常用 Result/Message。

## 4 接口约定（Mock 层）

- 统一 `list<T>` 入参：`{ page, pageSize, ...filters }`；返回 `{ list: T[]; total: number }`。
- 写操作返回更新后的对象或 `{ ok: true }`；Mock 用内存 + `localStorage`（权限/订阅/已读/处置/下载留痕）持久化。
- 供方范围过滤：所有含 `supplierId` 的查询在 api 层依据会话用户 `supplierScope: string[] | '*'` 强制过滤。
- 会话结构（v8User store）：`{ token, userInfo }`，`userInfo` 字段见 6.1「会话用户」。
