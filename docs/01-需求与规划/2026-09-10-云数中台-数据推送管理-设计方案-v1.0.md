# 云数中台-数据推送管理设计方案

## 一、项目概述

### 1.1 背景

云数中台已具备接入侧能力（接入方案、机构供数、字段库、IP 白名单等），机构数据入库后，需要把本机构已沉淀数据按约定通道回推至机构侧接收端。现有「数据推送管理」原型仍以独立「使用方」+ JDBC 源端外推任务为主，与当前「只推中台已入库数据、使用方即机构」的业务口径不一致，需按本期正式能力重设计。

### 1.2 目标

本期将「数据推送管理」做成可配置、可启停的正式一期能力：

- 运维维护可复用的**推送方案**（通道、鉴权、频次、批量、增量/全量）；
- 将方案挂到**机构推送任务**并启停；
- 推送范围固定为该机构**全部已入库数据**（不跨机构、不按接入方案再切分）；
- 任务列表展示运行态与简易汇总；量级统计分析纳入后续「数据概览」（现「供数统计」更名后的扩展）。

### 1.3 核心价值

- 与接入管理对称：方案模板 + 机构挂接，降低重复配置；
- 通道与接入对齐（HTTP / MQ / 文件预留），降低联调认知成本；
- 配置与总览统计分离：推送模块管「怎么配、跑得怎样」，数据概览管「接入 + 外推整体量」。

### 1.4 设计原则（已确认）

| 项 | 口径 |
|----|------|
| 交付目标 | 正式一期：配置 + 启停（非仅演示） |
| 数据来源 | 仅中台已入库数据 |
| 使用方 | 机构本身，无独立使用方主数据 |
| 跨机构 | 不支持 |
| 通道 | 三种对齐接入；本期只实现 HTTP、MQ；文件禁用预留 |
| 频次 | Cron 或固定间隔（分钟）+ 批量条数上限 |
| 推送模式 | 增量 / 全量，配置在推送方案内 |
| 导航 | 一级「数据推送管理」下两个二级页 |
| 任务基数 | 一机构可多任务，但同一通道类型仅一条；启用与停用均占坑 |
| 统计 | 任务侧简易运行态；整体分析在「数据概览」 |

## 二、功能范围

### 2.1 本期范围（In Scope）

| 模块 | 能力说明 |
|------|----------|
| 导航改造 | 一级「数据推送管理」下设二级：「推送方案」「机构推送任务」；替换原「使用方 / 外推任务」Tab 结构 |
| 推送方案 | 增删改查、启停、名称唯一；通道 HTTP/MQ（文件禁用）；鉴权结构化；频次 Cron/间隔；批量上限；增量/全量 |
| 机构推送任务 | 选机构 + 挂推送方案 + 启停；数据范围固定为该机构全部已入库；同机构同通道类型唯一（启停均占坑） |
| 运行态 | 任务列表展示最近运行状态、成功/失败次数、最近失败原因；列表上方简易 KPI 汇总 |
| 与概览边界 | 外推量级/成功率等整体分析归入后续「数据概览」（现供数统计）；本模块不建独立复杂看板 |

### 2.2 本期不做（Out of Scope）

- 独立「使用方 / Consumer」主数据与维护页
- 跨机构订阅或向非本机构推送
- 任务级「选择接入方案 / 字段子集」裁剪
- 文件传输通道实配与联调
- 真实调度引擎、对端真实联调（原型以 Mock 持久化与模拟运行态为准）
- 「供数统计」更名「数据概览」及外推图表的完整实现（另开迭代，本设计只定接口边界）
- 原原型中的 JDBC/源库/Schema 作为外推数据源的配置方式

### 2.3 与既有模块关系

| 既有模块 | 关系 |
|----------|------|
| 接入方案 / 机构供数 | 负责数据如何进入中台；外推不反向绑定接入方案，只消费机构已入库结果 |
| 字段库 | 间接影响入库结构；推送方案本期不维护字段清单 |
| IP 白名单 | 管接入来源 IP；外推鉴权在推送方案内配置，不复用白名单 |
| 供数统计 → 数据概览 | 后续承接接入 + 外推整体统计分析 |

## 三、核心模块设计

### 3.1 信息架构与路由

```
数据推送管理（一级菜单）
├── 推送方案           路由建议：/push/schemes
└── 机构推送任务       路由建议：/push/tasks
```

- 废弃原 `/push` 单页双 Tab（使用方 / 外推任务）交互与「源库 JDBC」字段模型。
- 侧栏：一级可展开为两个二级菜单项（与「接入管理」下多子页风格一致即可）。

### 3.2 推送方案

#### 3.2.1 列表

| 列 | 说明 |
|----|------|
| 方案名称 | 唯一 |
| 通道类型 | HTTP / MQ / 文件（文件仅展示历史或不可新建） |
| 推送模式 | 增量 / 全量 |
| 频次摘要 | 如 `Cron: 0 */1 * * *` 或 `每 30 分钟` |
| 状态 | 启用 / 停用 |
| 更新时间 | — |
| 操作 | 详情、编辑、启停；可选「复制新增」 |

#### 3.2.2 表单分区

**（1）基础信息**

- 方案名称（必填、全局唯一）
- 状态（启用/停用）
- 备注

**（2）推送通道**（与接入侧三种对齐，语义改为「中台 → 机构」）

- 通道类型：HTTP | 消息队列 | 文件（文件选项可见但禁用）
- **HTTP**：对端接口地址、协议、请求方法（默认 POST）、鉴权方式、Token/Header/AppKey 类结构化字段、可选自定义请求头、重试次数等（字段语义对齐 `AccessMethodForm` 中 HTTP 区，方向为外呼）
- **MQ**：Broker/连接信息、Topic 或 Queue、鉴权与必要连接项（对齐接入 MQ 区）

**（3）推送策略**

- 推送模式：增量 | 全量（用户必选）
- 频次类型：Cron 表达式 | 固定间隔（分钟）
- 批量条数上限（必填，正整数）
- 失败重试：可与通道区合并展示，避免重复录入

#### 3.2.3 交互规则

- 已有机构任务引用的方案：允许编辑策略与鉴权；若变更**通道类型**，保存前校验是否导致某机构「同通道类型重复」；冲突则阻止并提示已有任务。
- 方案停用：不允许被新任务选用；已挂接且仍启用的任务给出提示，建议运维停用任务（原型可强校验：方案停用时关联任务不可保持启用）。

### 3.3 机构推送任务

#### 3.3.1 列表与简易汇总

**列表上方 KPI（简易）**：任务总数、启用中、近 24h 失败任务数（Mock 即可）。

| 列 | 说明 |
|----|------|
| 机构 | 目标机构 |
| 推送方案 | 名称 |
| 通道类型 | 来自方案 |
| 任务状态 | 启用 / 停用 |
| 最近运行状态 | 成功 / 失败 / 运行中 / 未运行 等 |
| 成功次数 / 失败次数 | 累计或窗口内，原型约定一种即可 |
| 最近失败原因 | 摘要文案 |
| 更新时间 | — |
| 操作 | 编辑、启停 |

#### 3.3.2 新建 / 编辑

| 字段 | 规则 |
|------|------|
| 机构 | 必选 |
| 推送方案 | 必选；下拉展示名称 + 通道类型；仅可选「启用」方案 |
| 数据范围 | 只读说明：「推送该机构全部已入库数据」；不出现接入方案选择器 |
| 任务状态 | 启用 / 停用 |

#### 3.3.3 唯一性与启停

- 约束键：`机构 ID + 通道类型`（通道类型取自所选推送方案）。
- **启用与停用均占坑**：同一机构同一通道类型至多一条任务记录，避免重复配置。
- 保存时冲突：拦截并指出已存在任务入口。

### 3.4 与「数据概览」的边界

| 能力 | 归属 |
|------|------|
| 方案/任务配置、启停、任务运行态与简易 KPI | 数据推送管理 |
| 接入供数量 + 外推量/成功率等整体趋势与交叉分析 | 供数统计 → 更名后的「数据概览」（后续迭代） |

本期推送模块需保证任务侧可产出可被概览消费的指标字段（成功条数、失败条数、机构、时间等），具体图表不在本设计展开。

## 四、数据结构与流向

### 4.1 核心实体

**PushScheme（推送方案）**

| 字段 | 说明 |
|------|------|
| id | 主键 |
| name | 名称，唯一 |
| status | enabled / disabled |
| channelType | http / mq / file |
| channelConfig | 通道与鉴权结构化配置（按类型分支） |
| pushMode | incremental / full |
| scheduleType | cron / interval |
| cronExpr / intervalMinutes | 与 scheduleType 对应 |
| batchLimit | 批量条数上限 |
| remark | 备注 |
| updatedAt | 更新时间 |

**OrgPushTask（机构推送任务）**

| 字段 | 说明 |
|------|------|
| id | 主键 |
| orgId | 机构 |
| schemeId | 推送方案 |
| channelType | 冗余自方案，便于唯一约束与列表展示 |
| status | enabled / disabled |
| lastRunStatus | success / failed / running / never 等 |
| successCount / failCount | 运行计数 |
| lastFailReason | 最近失败原因 |
| updatedAt | 更新时间 |

**唯一约束**：`(orgId, channelType)` 唯一。

**明确不存在的实体（本期）**：PushConsumer（使用方）、任务级 accessSchemeId、JDBC 源库配置。

### 4.2 数据流向

```
运维配置推送方案（通道 + 策略 + 鉴权）
        │
        ▼
运维创建机构推送任务（机构 + 方案；数据范围 = 该机构全部已入库）
        │
        ▼
调度触发（原型 Mock）→ 读取该机构已入库数据
        │                 ├─ 增量：自上次成功水位之后
        │                 └─ 全量：按方案全量策略
        ▼
按方案通道推送至本机构接收端（HTTP / MQ）
        │
        ▼
回写任务运行态 ──► 指标可供「数据概览」汇总（后续）
```

### 4.3 与接入数据的关系

- 入库由接入方案 + 机构供数完成；外推**不**选择接入方案。
- 一机构若通过多套接入方案入库，外推任务仍一次覆盖该机构全部已入库数据。
- 跨机构数据不可被本任务读出或推出。

## 五、边界情况处理

### 5.1 业务与校验异常

| 场景 | 处理 |
|------|------|
| 机构尚无任何已入库数据 | 允许创建任务；运行结果可为成功且推送条数 0 |
| 所选推送方案已停用 | 新建/编辑不可选；存量启用任务在方案停用时应被约束为不可保持启用（提示运维停用任务） |
| 同机构同通道类型已存在任务 | 保存拦截，提示已有任务（含停用记录） |
| 编辑方案变更通道类型导致唯一冲突 | 保存拦截并说明冲突机构任务 |
| 选择文件通道 | 选项禁用，不可提交 |
| 试图配置跨机构推送 | 无入口；数据范围始终限定本机构 |
| Cron / 间隔非法 | 表单校验，阻止保存 |
| 批量上限 ≤ 0 或空 | 表单校验，阻止保存 |

### 5.2 权限与角色（原型约定）

- 配置与启停面向中台运维账号；机构端不在本模块自助订阅。
- 细粒度 RBAC 若与现网权限模型冲突，以实现阶段与现有菜单权限对齐为准，本设计不新增独立权限码表。

### 5.3 原型验收要点（mt-web）

1. 侧栏一级下可进入「推送方案」「机构推送任务」两个二级页。
2. 推送方案支持 HTTP/MQ 配置与增量/全量、Cron/间隔、批量上限；文件通道禁用。
3. 机构任务可挂启用中的推送方案；数据范围只读为机构全量入库；同通道唯一校验生效。
4. 任务列表可见运行态与简易 KPI；无「使用方」主数据页；无 JDBC 源端配置。
5. Mock 数据可持久（或会话级持久）以支持演示启停与编辑回显。
